# Experiment Plan

Status: **plan (milestone 1)**. No results exist yet. Each experiment is one YAML config in `experiments/configs/` and one entry point:

```
python -m experiments.run --config experiments/configs/<id>.yaml --seeds 0 1 2 3 4
```

Every run writes `experiments/results/<id>/<UTC timestamp>/` containing the resolved config, git SHA, `pip freeze`, dataset manifest hashes, per-seed metrics (CSV/JSON) and figures (PNG + PDF). Tables in the paper are generated by `experiments/make_tables.py` from these folders only. No number is copied by hand.

Bracketed numbers like [21] refer to `RESEARCH_NOTES.md`.

## 0. Data, splits, and the composite-session protocol

Datasets are attached to Kaggle notebooks (see `training/datasets.yaml` and `docs/KAGGLE.md`). The original licenses apply. Every experiment must run with the Kaggle-available sets. Gated sets (DocTamper, OULU-NPU) are optional extras.

### 0.2 Splits
Splits are **subject-disjoint** train / calibration / validation / test (60/10/10/20). DF40 [18] and FF++ [14] use their official splits where they exist. The calibration split is used only for calibrators and conformal reference sets. The validation split is used only for fusion training, threshold selection and the sensitivity matrix. Test is touched once per final run.

### 0.3 Composite KYC sessions
A session is (ID image, selfie video, label, attack type). The rules:
- **Genuine:** an SIDTD bona fide ID template with a Celeb-DF/FF++ real frame of identity *X* pasted as the portrait, plus a *different* real video of *X* as the selfie.
- **Document attack:** an SIDTD forged ID with a genuine selfie.
- **Deepfake attack:** a genuine ID of victim *V* with a fake video using *V* as source identity.
- **Replay attack:** a genuine ID with an OULU/CelebA-Spoof replay or print video. Identity matching is not possible here, so M5 is marked `not_applicable` and this is logged.
- **Simulated attacks** for the offline sample only: SBI pseudo-fakes [20] and synthetic screen-replay (moiré, gamma and reflection overlays). These are **always labelled `simulated`** and never mixed into reported test metrics.

The protocol is a limitation and is stated in the paper: fraud signals across modules are independent by construction.

## 1. Metrics

- **Detection:** AUC, EER, APCER / BPCER / ACER (ISO/IEC 30107-3 [27], per attack type and worst-case), FAR/FRR for M5, and TPR at fixed FPR (1%, 5%).
- **Calibration:** ECE (15 bins) and MCE [56], Brier score, reliability diagrams.
- **Decision-level:** accept/review/reject rates, error rate among auto-decisions vs review rate (a risk–coverage curve), and the veto false-trigger rate.
- **Drift:** detection delay in sessions after onset, detection rate, false alarms per 10k stationary sessions, and feature-attribution hit@1 / hit@3 (is the injected feature ranked top?).
- **Novelty:** AUROC, FPR@95TPR, AUPR-in/out [80]; stream-level alert delay, alert precision, cluster purity.
- **Disambiguation:** macro-F1 over window labels {NONE, QUALITY_DRIFT, CONCEPT_DRIFT, OUTPUT_DRIFT, NOVEL_ATTACK, MIXED}, confusion matrix, and time to correct label.
- **Systems:** per-module CPU latency p50/p95, peak RSS, and end-to-end session time.
- **Uncertainty reporting:** mean ± std over 5 seeds plus 1000× bootstrap 95% CIs on test. Paired bootstrap is used for method comparisons. Any significance test that is not one of the verified methods in RESEARCH_NOTES gets added there before use.

## 2. Experiments

### E1 — Per-module performance and generalization
- M1: SIDTD hold-out and SIDTD few-shot protocol; DLC-2021 recapture with APCER at BPCER = 5% (protocol of [9]); cross-dataset to FantasyID if available.
- M2: FF++ → FF++ (in-domain), FF++ → Celeb-DF / DF40 (cross-dataset), following DeepfakeBench preprocessing [17]. Feature groups are ablated: CLIP only, + frequency, + temporal, + rPPG.
- M3: CelebA-Spoof intra; OULU-NPU protocols 1–4; CelebA-Spoof → OULU cross.
- M4: passive liveness (rPPG + blink + motion) on OULU live vs print/replay. POS is checked against the rPPG-Toolbox [40] outputs on the same clips (correlation of BVP signals).
- M5: verification ROC on Celeb-DF same/different-identity pairs; temporal stability (CV) of each geometric ratio vs head-pose bins.
- **Baselines:** ELA-only for M1 [1]; IDA-only for M3 [34]; MSP of a fine-tuned head vs a frozen-CLIP probe for M2 [21].

### E2 — Calibration
For each module: uncalibrated vs temperature scaling [54] vs isotonic [55]. Report ECE/MCE/Brier on clean data and under corruptions (from E5a). Hypothesis: calibration fitted on clean data degrades under quality drift, which motivates monitoring ECE as a performance-drift signal once labels arrive.

### E3 — Fusion ablation (main table)
- Strategies F0–F6 (ARCHITECTURE §6.2) × {clean test, corrupted test at severity 1–5}.
- **Leave-one-module-out** for the best strategy and for F1; each single module alone as a baseline.
- With vs without quality gating: F2 vs F4, F5 vs F6.
- Confidence quality: AUROC of module confidence for predicting the module's own correctness, for confidence types (a) evidential and (b) kNN-in-q reliability.
- Report AUC, EER, APCER@BPCER=1/5%, ECE, and the risk–coverage curve.
- **Hypothesis H3:** quality-aware fusion (F4/F6) holds attack detection and ECE better than F1/F2 as corruption severity rises, with no loss on clean data. *If the data do not support this, the result is reported as is.*

### E4 — Thresholds and veto
- `T_high` / `T_low` / `τ_veto` are chosen on validation for target operating points (APCER ≤ 1%, BPCER ≤ 2%, veto false trigger ≤ 0.1%). Test-set realized rates are reported with CIs, along with threshold stability across seeds.
- Effect of the veto: attacks caught only by the veto vs genuine sessions wrongly vetoed.

### E5 — Drift detection
**E5a, sensitivity matrix.** Corruptions are applied at 5 severities to the validation data: Gaussian blur σ, motion blur, downscale factor, JPEG quality, H.264 CRF (ffmpeg/PyAV re-encode), low light (gamma + gain + shot noise), Gaussian noise, colour shift (white-balance), and frame-rate drop (frame dropping and duplication). For each one, record the change in every q feature and the change in every module's AUC and ECE. This gives `S[module, feature]` for the recommender.

**E5b, stream benchmark.** `stream_simulator.py` builds time-ordered streams of composite sessions: 2,000 stationary sessions, then a drift onset at a known index. Onset is either abrupt or gradual (linear ramp over 500 sessions). Corruption type and severity are drawn from the E5a grid. Each stream has 20 repetitions per configuration with different seeds.

Detectors compared:
- per-feature KS / Wasserstein / PSI / JS with BH [65], with PSI critical values per [66];
- MMD [60] on Q, on PCA-reduced A, and on scores;
- C2ST [61];
- ADWIN [67] / Page–Hinkley [70] on the fused-score stream;
- DDM [68] / EDDM [69] on the delayed review-label error stream, with label delay and label rate (10%, 30%) as parameters;
- reference implementations (river [71], alibi-detect, evidently) as sanity oracles only.

Window sizes are {100, 250, 500} with step 50, matching the small-sample concern in [62].

Report delay, detection rate, false alarms per 10k sessions, and attribution hit@1/3.

### E6 — Novel-attack detection (leave-one-generator-out)
- **Primary:** DF40 [18]. Train M2 on k generators and hold out one family at a time (face-swap, reenactment, entire-face synthesis), rotating over 5–8 held-out techniques. **Secondary:** FF++ leave-one-method-out (DF, F2F, FS, NT, FaceShifter) [14].
- Known classes = {genuine, each known attack type (including replay and document attack)}. OOD methods: MSP, energy [73], ODIN [74], Mahalanobis [72], kNN [75], Deep SVDD [76], Isolation Forest [77], LOF [78], OpenMax-lite [79]. Each is evaluated in the M2 CLIP space and in the concatenated artifact space.
- **Sample level:** AUROC, FPR@95TPR, AUPR.
- **Stream level:** the held-out generator is injected at a known onset with prevalence {1%, 5%, 10%} of sessions. Report conformal binomial test detection delay [81], HDBSCAN cluster alert delay [82], alert precision, and cluster purity.
- Morphing as a novel *document* attack: optional, only if a public morph set with a suitable license is identified [13]. Otherwise listed as future work.

### E7 — Drift vs novelty disambiguation (central contribution)
Scenarios, 20 seeded streams each:

| ID | Injection | Expected label |
|---|---|---|
| S0 | none | NONE |
| S1 | quality corruption (E5 grid), all classes | QUALITY_DRIFT |
| S2 | held-out generator at 5% prevalence, clean capture | NOVEL_ATTACK |
| S3 | S1 and S2 simultaneously | MIXED |
| S4 | prevalence of a *known* attack rises 2%→10% | OUTPUT_DRIFT / PRIOR_SHIFT (not novelty) |
| S5 | quality corruption applied *only* to attack sessions (an adversarial confounder) | must not be labelled pure QUALITY_DRIFT; the A\|Q test should fire |
| S6 | gradual sensor change (OULU-NPU unseen-phone protocol as natural drift [28]) | QUALITY_DRIFT |

Methods compared:
- (a) any-drift-test-fires ⇒ "drift";
- (b) OOD-rate only ⇒ "novelty";
- (c) MINAS-style cluster-then-decide [84] without quality conditioning;
- (d) the proposed rule (ARCHITECTURE §9);
- (e) the proposed rule without the conformal binomial test (heuristic OOD threshold);
- (f) the proposed rule without the quality-conditional reweighting.

Report macro-F1, confusion matrices, time to correct label, and calibration of the output confidence. The (e) and (f) rows are the ablations that justify each component.

### E8 — Does the recommendation help? (closed loop)
For each S1 corruption, apply three fixes: (i) the recommended action (augment the named module with the named corruption and recalibrate), (ii) random augmentation with the same compute budget, (iii) recalibration only. Report recovered AUC/ECE of the module and of the fused system on post-drift data, using a held-out post-drift test segment.

### E9 — Latency and resources
CPU-only profile on the development machine and inside the Docker image: per-module p50/p95, end-to-end time, RAM, model download sizes. Hardware is reported exactly as measured.

### E10 — Bias and failure audit (limitations section)
- Per-attribute error rates on CelebA-Spoof attributes [30] (illumination, environment) and, where datasets provide them, demographic metadata. Report gaps; do not claim fairness.
- Check whether novelty clusters align with demographic groups rather than attack types (cluster–attribute mutual information).
- Curated failure gallery: dark skin under low light vs rPPG SNR, glasses vs EAR, heavy compression vs M2.

## 4. Compute budget (CPU-only assumption)

- Feature extraction is the bottleneck: CLIP ViT-B/16 at about 0.1–0.3 s per face crop on CPU, an estimate to be confirmed in E9. At 16 frames per video, FF++ c23 (about 5k videos) needs roughly 2–6 CPU-hours. Embeddings are cached once to `data/processed/`.
- Heads, calibrators, fusion, drift and novelty experiments run on cached features and take minutes per seed.
- GPU is only needed for the optional deep backends (TruFor, CDCN, SBI-EfficientNet). They are excluded from the main tables unless you provide GPU access.

## 5. Offline end-to-end sample (no downloads beyond model weights)

`python -m experiments.run --config experiments/configs/smoke.yaml` will:
1. generate synthetic ID cards (procedural templates with ICAO-valid MRZ [12] and no real persons; portrait slot filled from your own recorded selfie or left blank);
2. take a short genuine clip you record via Dashboard 1, or a CC-BY sample if you approve one;
3. create simulated attacks (SBI pseudo-fakes, synthetic replay overlays, forged MRZ/fields);
4. run all modules, fusion, a 300-session simulated stream with injected blur drift and an injected simulated-novel attack, and produce every figure type.

All outputs are watermarked "SMOKE TEST – SIMULATED DATA, NOT RESULTS".
